# 任务健康监控 - 快速使用指南

## 快速开始

### 1. 启用健康监控（默认已启用）

健康监控默认启用，如需禁用可在 `.env` 文件中设置：

```bash
ENABLE_HEALTH_MONITOR=false
```

### 2. 自定义配置（可选）

在 `.env` 文件中添加以下配置：

```bash
# 任务检查间隔（秒），默认300秒（5分钟）
TASK_HEALTH_CHECK_INTERVAL=300

# 视频流检查间隔（秒），默认600秒（10分钟）
STREAM_HEALTH_CHECK_INTERVAL=600

# 基础重试延迟（秒），默认300秒（5分钟）
RETRY_DELAY_BASE=300

# 最大重试延迟（秒），默认3600秒（1小时）
MAX_RETRY_DELAY=3600

# 最大连续失败次数，默认5次
MAX_CONSECUTIVE_FAILURES=5
```

### 3. 启动系统

```bash
cd backend
python main.py
```

启动日志中会显示：
```
🔄 开始启动任务健康监控服务...
✅ 任务健康监控服务已启动
```

## 常见场景

### 场景1：视频流短暂掉线

**问题：** 网络抖动导致RTSP流短暂断开

**自动处理：**
1. 健康检查发现任务未运行
2. 检查视频流状态，发现流离线，暂不恢复
3. 流监控定期检查，发现流已恢复
4. 自动重启相关的分析任务
5. ✅ 任务恢复正常

**日志示例：**
```
WARNING - ⚠️  发现任务未运行: 摄像头1_未佩戴安全帽_分析任务
INFO - 暂不恢复任务: 等待流恢复
INFO - ✅ 视频流已恢复: 摄像头1
INFO - 🔄 尝试恢复任务: 摄像头1_未佩戴安全帽_分析任务
INFO - ✅ 任务恢复成功
```

### 场景2：任务意外停止

**问题：** 任务因某种原因停止，但视频流正常

**自动处理：**
1. 健康检查发现任务未运行
2. 检查视频流状态，发现流在线
3. 立即尝试恢复任务
4. ✅ 任务恢复成功

**日志示例：**
```
WARNING - ⚠️  发现任务未运行: 摄像头1_未佩戴安全帽_分析任务
INFO - 🔄 尝试恢复任务: 摄像头1_未佩戴安全帽_分析任务
INFO - ✅ 任务恢复成功
```

### 场景3：持续性问题（智能重试）

**问题：** 任务因配置错误持续失败

**自动处理：**
1. 第1次失败 → 5分钟后重试
2. 第2次失败 → 10分钟后重试
3. 第3次失败 → 10分钟后重试
4. 第4次失败 → 20分钟后重试
5. 第5次失败 → 20分钟后重试
6. 第6次及以后 → 1小时后重试

**重试策略：** 指数退避，避免频繁重试浪费资源

## 监控指标说明

### 健康分数（health_score）

范围：0-100，越高越好

**计算逻辑：**
- 基础分：100分
- 问题任务扣分：每个问题任务按比例扣分（最多30分）
- 离线流扣分：每个离线流按比例扣分（最多30分）
- 失败率扣分：根据恢复失败率扣分（最多40分）

**分数含义：**
- 90-100分：优秀，系统运行良好
- 70-89分：良好，有少量问题
- 50-69分：一般，需要关注
- 0-49分：差，需要立即处理

### 任务统计

- **total_tasks_monitored** - 监控的任务总数
- **tasks_with_failures** - 曾经失败过的任务数
- **tasks_with_consecutive_failures** - 当前连续失败的任务数

### 流统计

- **total_streams_monitored** - 监控的视频流总数
- **online_streams** - 在线的视频流数
- **offline_streams** - 离线的视频流数

### 恢复统计

- **total_checks** - 总检查次数
- **total_recoveries** - 成功恢复次数
- **total_failures** - 恢复失败次数

## 故障排查

### 1. 监控服务未启动

**检查：**
```bash
curl http://localhost:16532/api/task-health/status
```

**如果返回服务未运行：**
- 检查 `.env` 中 `ENABLE_HEALTH_MONITOR` 是否为 `true`
- 查看启动日志是否有错误信息
- 重启系统

### 2. 任务持续恢复失败

**检查：**
```bash
curl http://localhost:16532/api/task-health/task-records
```

**查看连续失败次数和最后错误信息：**
```json
{
  "consecutive_failures": 5,
  "last_error": "RTSP流健康检查失败: 连接超时"
}
```

**可能原因：**
- 视频流地址错误
- 网络不通
- 算法配置错误
- 权限问题

### 3. 视频流显示离线

**检查：**
```bash
curl http://localhost:16532/api/task-health/stream-records
```

**手动测试RTSP流：**
```bash
ffmpeg -i "rtsp://..." -frames:v 1 test.jpg
```

## 性能优化建议

### 调整检查间隔

**场景1：高可用性要求**
```bash
# 更频繁的检查
TASK_HEALTH_CHECK_INTERVAL=60    # 1分钟
STREAM_HEALTH_CHECK_INTERVAL=120 # 2分钟
```

**场景2：降低系统负载**
```bash
# 较长的检查间隔
TASK_HEALTH_CHECK_INTERVAL=600   # 10分钟
STREAM_HEALTH_CHECK_INTERVAL=1800 # 30分钟
```

### 调整重试策略

**场景1：快速恢复**
```bash
# 更短的重试延迟
RETRY_DELAY_BASE=60      # 1分钟
MAX_RETRY_DELAY=600      # 10分钟
```

**场景2：减少重试频率**
```bash
# 更长的重试延迟
RETRY_DELAY_BASE=600     # 10分钟
MAX_RETRY_DELAY=7200     # 2小时
```

## 最佳实践

### 1. 监控告警集成

虽然当前版本只记录日志，但建议：
- 将健康分数低于70时发送告警
- 监控连续失败次数超过3的任务
- 关注离线流数量异常增加

### 2. 定期查看监控报告

建议每天查看一次监控概览：
```bash
curl http://localhost:16532/api/task-health/summary
```

### 3. 配置合理的检查间隔

- 任务检查间隔：5-10分钟（默认5分钟）
- 流检查间隔：10-30分钟（默认10分钟）
- 不建议低于1分钟，避免过度消耗资源

### 4. 查看恢复历史

定期查看任务恢复记录，了解系统稳定性：
```bash
curl http://localhost:16532/api/task-health/task-records | jq '.data[] | select(.failure_count > 0)'
```
