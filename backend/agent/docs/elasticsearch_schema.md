# 告警分析系统 Elasticsearch 索引字段说明

本文档详细说明了告警分析系统中使用的Elasticsearch索引结构,用于AI智能体的语义理解和数据查询。

---

## 1. video_alerts (告警索引)

存储视频分析产生的所有告警记录,是告警分析的核心数据源。

### 1.1 核心标识字段

| 字段名 | 类型 | 说明 |
|--------|------|------|
| **task_id** | keyword | 分析任务的唯一标识符,用于关联同一次分析任务的所有数据 |
| **video_id** | keyword | 视频文件的唯一标识符,用于区分不同的视频源 |
| **stream_id** | keyword | RTSP视频流的唯一标识符,用于实时流分析场景 |
| **video_name** | text | 视频文件或视频流的名称,便于用户识别 |
| **camera_name** | text | 产生告警的摄像头名称,用于位置定位和分析 |

### 1.2 时间相关字段 ⚠️ 重要

| 字段名 | 类型 | 说明 | 使用场景 |
|--------|------|------|----------|
| **frame_index** | integer | 告警发生的视频帧编号,用于精确定位告警时刻 | 视频帧定位 |
| **timestamp** | float | ⚠️ **标准UTC Unix时间戳**（从1970-01-01 00:00:00 UTC开始的秒数）,与时区无关,全球统一 | 技术计算、时间排序 |
| **video_time** | keyword | 告警在视频中的时间位置(HH:MM:SS格式),便于人工回溯 | 视频回溯 |
| **datetime** | date | ⚠️ **告警实际发生的北京时间**（从timestamp转换而来，对于离线视频可能是几天前） | 分析告警发生的实际时间分布 |
| **created_at** | date | ✅ **告警记录被保存到系统的时间**（当前北京时间，推荐用于统计） | **统计"今天"、"本周"的告警数量** |

**⚠️ 关键区别说明**：
- **timestamp**: UTC Unix时间戳
  - 标准格式，与时区无关，全球统一
  - 示例：`1760955371.1178787`（对应北京时间2025-10-20 18:16:11）
  - 用途：技术计算、时间排序、跨时区数据交换

- **datetime**: 告警实际发生的北京时间
  - 从timestamp转换而来（UTC+8）
  - 实时流分析：接近当前北京时间
  - 离线视频分析：视频拍摄的北京时间（可能是几天前、几周前）
  - 示例：`2025-10-20T18:16:11.117879`
  - 用途：分析告警在一天中什么时段高发、视频事件回溯

- **created_at**: 告警记录被创建/保存的时间
  - 始终是系统记录该告警的时间（当前北京时间）
  - 示例：`2025-10-20T18:16:20.266813+08:00`
  - 用途：**统计"今天有多少告警"、"本周告警趋势"等业务查询**
  - ✅ **推荐用于时间范围统计查询**

**示例场景**：
- 场景：今天(10-23 14:00)分析了一个10-20拍摄的视频
- `timestamp`: 1729407600.0（UTC时间戳）
- `datetime`: 2025-10-20 10:00:00（视频拍摄的北京时间）
- `created_at`: 2025-10-23 14:00:00（今天系统记录的北京时间）
- 查询"今天有多少告警"：应使用 `created_at`，否则会漏掉这条告警

### 1.3 算法相关字段

| 字段名 | 类型 | 说明 |
|--------|------|------|
| **template_name** | text | 触发告警的AI分析模板名称(如"安全帽检测模板"),这就是告警类型 |
| **algorithm_name** | text | 使用的AI算法名称(如"未戴安全帽检测"、"吸烟检测"等),这就是告警类型 |
| **algorithm_category** | keyword | 算法所属的大类(如"安全检测"、"行为分析"等) |
| **analysis_type** | keyword | 分析类型标识: video_analysis(离线分析)或stream_analysis(实时分析) |
| **ai_response** | text | AI模型返回的原始分析结果文本,包含完整的推理过程 |

### 1.4 告警内容字段

| 字段名 | 类型 | 说明 |
|--------|------|------|
| **confidence** | float | 告警的置信度分数(0.0-1.0),表示AI判断的确信程度 |
| **description** | text | 告警的文字描述,人类可读的告警说明 |
| **alert_content** | text | 告警的详细内容信息,可能包含结构化数据 |
| **detection_details** | object | 检测到的具体对象和细节(嵌套对象),包含边界框、类别等 |

### 1.5 严重程度字段

| 字段名 | 类型 | 说明 |
|--------|------|------|
| **severity** | keyword | 告警严重等级:low(低)、medium(中)、high(高)、critical(严重) |
| **alert_level** | keyword | 告警的级别分类,用于告警分级处理 |
| **priority** | integer | 告警处理优先级(数值型),越大越优先,用于排序 |
| **category** | keyword | 告警所属的业务类别,如"安全违规"、"设备异常"等 |

### 1.6 位置和状态字段

| 字段名 | 类型 | 说明 |
|--------|------|------|
| **location** | text | 告警发生的物理位置或区域,如"车间A区"、"大门口"等 |
| **resolved** | boolean | 告警是否已被解决(true/false),用于告警闭环管理 |
| **image_url** | keyword | 告警截图的访问地址,用于查看告警现场 |
| **metadata** | object | 其他扩展信息(嵌套对象),用于存储自定义字段 |
| **data_type** | keyword | 数据来源类型标识,如"video"、"stream"等 |

## 2. video_frame_results (视频帧分析结果索引)

存储每一帧视频的AI分析结果,包括有告警和无告警的帧,用于完整的视频分析追溯。

### 2.1 核心字段

| 字段名 | 类型 | 说明 |
|--------|------|------|
| **task_id** | keyword | 所属分析任务的ID,用于关联任务 |
| **video_id** | keyword | 所属视频的ID,用于关联视频 |
| **frame_index** | integer | 视频帧的序号,从0开始递增 |
| **timestamp** | float | 该帧的Unix时间戳,用于时间序列分析 |
| **video_time** | keyword | 该帧在视频中的时间位置(HH:MM:SS) |

### 2.2 分析结果字段

| 字段名 | 类型 | 说明 |
|--------|------|------|
| **template_id** | keyword | 使用的分析模板ID,用于关联模板配置 |
| **template_name** | text | 使用的分析模板名称,便于用户理解 |
| **ai_response** | text | AI模型对该帧的完整分析结果,包含识别的所有内容 |
| **confidence** | float | 分析结果的置信度(0.0-1.0),表示AI的确信程度 |
| **has_alert** | boolean | 该帧是否产生了告警(true/false),用于快速筛选告警帧 |

### 2.3 辅助字段

| 字段名 | 类型 | 说明 |
|--------|------|------|
| **analyzed_at** | date | 该帧被分析的时间,用于性能分析和审计 |
| **image_url** | keyword | 该帧图片的访问地址,用于查看原始画面 |
| **detection_objects** | nested array | 检测到的所有对象列表(嵌套数组),详细结构如下 |

#### detection_objects 子字段结构:

| 子字段名 | 类型 | 说明 |
|----------|------|------|
| **class_name** | keyword | 检测对象的类别名称,如"person"、"helmet"、"cigarette"等 |
| **confidence** | float | 该对象检测的置信度(0.0-1.0) |
| **bbox** | object | 对象的边界框坐标,包含x、y、width、height等属性 |

#### 严重程度分析类

## 4. 索引使用说明

### 4.1 查询建议

1. **时间范围查询 ⚠️ 重要**:
   - **统计类查询**（如"今天有多少告警"、"本周告警数量"）：**必须使用 `created_at` 字段**
   - **分析类查询**（如"上午告警多还是下午多"、"夜间告警分布"）：使用 `datetime` 字段
   - 原因：`created_at` 是系统记录时间，`datetime` 是告警实际发生时间（离线视频可能是几天前）
2. **全文检索**: 使用 `ai_response`、`description`、`alert_content` 进行关键词搜索
3. **精确匹配**: 使用 `alert_type`、`severity`、`algorithm_category` 等keyword字段
4. **数值统计**: 对 `confidence`、`priority` 等float/integer字段进行聚合分析
5. **嵌套查询**: 使用nested query查询 `detection_objects` 等嵌套字段

### 4.2 常用聚合分析

**⚠️ 重要提示**：对text类型字段做聚合时，**必须使用.keyword后缀**！

1. **terms聚合**: 按 `algorithm_name.keyword`、`template_name.keyword`、`location.keyword`、`camera_name.keyword`、`video_name.keyword` 分组统计
   - ❌ 错误示例: `"field": "algorithm_name"` (会报错！)
   - ✅ 正确示例: `"field": "algorithm_name.keyword"`
2. **date_histogram聚合 ⚠️ 重要**: 按时间维度(小时/天/周/月)统计告警趋势
   - **统计告警记录趋势**（如"每天新增告警数"）：使用 `created_at` 字段
   - **分析告警发生时段**（如"上午vs下午告警分布"）：使用 `datetime` 字段
3. **stats聚合**: 计算 `confidence` 的平均值、最大值、最小值、标准差
4. **range聚合**: 将 `confidence` 分段统计(如0-0.5、0.5-0.8、0.8-1.0)
5. **keyword字段聚合**: 对`severity`、`algorithm_category`、`analysis_type`、`data_type`等keyword类型字段可以直接聚合，无需.keyword后缀

### 4.3 性能优化建议

1. **分页查询**: 大量数据时使用 `from` 和 `size` 参数分页,避免深度分页
2. **字段过滤**: 使用 `_source` 参数只返回需要的字段,减少网络传输
3. **缓存利用**: 对于固定查询,利用ES的query cache提升性能
4. **索引别名**: 使用索引别名实现索引的滚动更新和零停机切换
